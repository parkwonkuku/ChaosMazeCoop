# 인증·플랫폼: 저장과 계정 연동의 실패 처리

[게임 소개](../../README.md) · [전체 사례](../case-studies.md) · [코드 가이드](../code-guide.md)

**S / 상황**

인증, 개인 기록 저장과 랭킹 제출은 서로 다른 단계에서 실패할 수 있습니다. 계정 연동·해제 요청도 중복되거나 다른 계정과 이미 연결된 상태일 수 있습니다.

**T / 과제**

인증·저장·랭킹 제출의 단계별 실패 처리를 분리하고, 계정 연동 오류를 구분해 처리해야 했습니다.

**A / 처리 순서와 오류 구분**

[SubmitRunRecordUseCase](../../src/Records/SubmitRunRecordUseCase.cs)에서 초기화 → 프로필 저장 → 개인 기록 저장 → 리더보드 제출 순서를 명시했습니다. 앞선 단계의 실패 Result는 반환하고, 리더보드 제출 Result와 개인 기록 저장 결과를 구분했습니다.

Google Play Games 계정 연동·해제 시 중복 요청과 타 계정 연결 오류를 구분해 처리했습니다. 계정 연동 어댑터는 공개 코드에서 생략했습니다.

**R / 결과의 분리**

리더보드가 실패 Result를 반환해도 이미 저장된 개인 기록 결과는 유지합니다. 계정 연동·해제는 요청 상태와 오류 유형을 나눠 처리하도록 구성했습니다.



## 저장 단계별 결과 처리

| 단계 | 실패 Result를 받은 경우 |
|---|---|
| 초기화·인증 | 실패를 반환하고 이후 저장·제출 중단 |
| 현재 프로필 저장 | 실패를 반환하고 개인 기록·랭킹 제출 중단 |
| 개인 기록 저장 | 저장 결과를 반환하고 랭킹 제출 중단 |
| 리더보드 제출 | 이미 얻은 개인 기록 저장 결과 유지 |

### 코드 발췌: 개인 기록 결과 유지

```csharp
await leaderboard.SubmitAsync(
    record, profileStore.Current.Nickname, cancellationToken);
return saveResult;
```

이 부분은 [SubmitRunRecordUseCase](../../src/Records/SubmitRunRecordUseCase.cs)의 실제 호출 순서를 보여줍니다. 리더보드의 실패 Result와 개인 기록 저장 결과를 분리하며, 예외나 취소까지 성공으로 바꾸는 처리는 아닙니다.

## 계정 연동 기능의 공개 범위

Google Play Games 계정 연동·해제와 중복 요청·타 계정 연결 오류 구분은 이력서에 기재한 구현 범위입니다. 해당 어댑터와 서비스 설정은 이 공개 저장소에서 생략했습니다. 공개 파일로 확인할 수 있는 저장 순서와, 설명만 제공하는 계정 연동 범위를 구분했습니다.
